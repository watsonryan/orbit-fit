# Numerical design

The present factor graph has one variable containing six normalized mean-element coordinates, or seven with BSTAR, connected to a state factor for each selected epoch. Ceres represents the variable as a parameter block and each factor as a residual block. The library does not expose Ceres or Eigen types in its installed API.

Mean motion is represented by its logarithm. Eccentricity uses a two-component vector with magnitude `e/sqrt(1-e²)`. The inclination chart uses `tan(i/2)` on the prograde side and `tan((pi-i)/2)` on the retrograde side, resolved along the node angle. Longitude of periapsis is `omega + sign*Omega`, with sign +1 prograde and -1 retrograde. Mean longitude is `M + longitude_of_periapsis`. The chart is chosen at initialization and kept fixed during a solve. Coordinate increments are scaled by 1e-3; BSTAR increments by 1e-4. This avoids a raw mixture of degrees, revolutions/day, and small drag coefficients in the optimizer.

Each factor initializes a fresh Vallado propagation record and returns predicted minus supplied TEME state in SI units. A fresh record makes deep-space propagation independent of call order and avoids sharing its mutable resonance integrator state between threads. The epoch and BSTAR remain mean-element model parameters, not a numerical-force-model state.

Jacobians default to forward-mode automatic differentiation using `ceres::Jet<double, 7>`. Six-parameter fits leave the seventh tangent zero and return six columns. The C++ scalar-templated SGP4 adaptation differentiates the complete chain: normalized coordinates, mean elements, initialization coefficients, deep-space terms, propagation, and the SI residual. The epoch, observation time, gravity constants, and chart selection are fixed. The derivative evaluator exposes values and Jacobians from the same Jet evaluation. The Ceres cost adapter uses its Jacobian with reference-kernel residuals in both callback modes, ensuring that requesting derivatives cannot alter the objective through last-bit rounding differences. It whitens both exactly once, then passes them to Ceres, whose loss function applies robust weighting. Both differentiation and estimation use Ceres; no Python runtime or generation step is involved.

Value-only evaluations, public propagation, and finite-difference checks use the unmodified Vallado kernel. Tests compare the adaptation's double and AD values against this reference and against the public verification corpus. This checks the derivative machinery against a separate, unmodified execution path; both propagators share the same underlying SGP4 equations and lineage.

The experimental `residual_curvature` API evaluates the same chart and SGP4 equations with nested Ceres Jets, returning unwhitened residuals, Jacobians, and a Hessian per residual component. It runs only on explicit request. This supports inspecting the residual-curvature term omitted by Gauss–Newton; the ordinary Ceres solver still consumes residuals and Jacobians. See [second-order derivatives](curvature.md) for coordinates, whitening and robust-objective formulas, validation, and measurements.

`Derivatives::finite_difference` / JSON `"derivatives": "finite_difference"` explicitly selects the previous central difference with step 1e-4 in normalized coordinates, or a one-sided difference if only one neighboring model is valid. It is retained for diagnosis and benchmarks; there is no silent fallback from AD. Step sweeps show why a single numerical perturbation is inadequate at nearly equatorial orbits and for tiny BSTAR sensitivities. The cost adapter returns `false` for invalid models so Ceres can reject the trial and shrink its trust region. Invalid initial or final models are reported as errors.

SGP4 remains piecewise smooth. AD follows the executed branches, including eccentricity clamps, resonance selection, and the bounded Kepler iteration. The angle-remainder derivative preserves the original `fmod` value and differentiates its local branch; tests cross angular wraps in the physical state. No two-sided derivative is claimed at a true model discontinuity. Exactly zero eccentricity or plane-vector magnitude makes the chart's `atan2`/norm derivatives undefined: AD reports that explicitly rather than emitting NaNs or silently perturbing the model. Near-circular, near-equatorial, retrograde, branch-adjacent, and resonant cases are tested, but decay boundaries and extreme geometries still need wider qualification.

Approximation mode minimizes a time-weighted design error. Selected samples receive normalized Voronoi cell widths in time, bounded by the requested window. Optional decimation picks evenly spaced **indices**, retaining endpoints; the time weights handle irregular cadence. Huber thresholds are adjusted with those weights so the robust objective retains the intended per-sample threshold. Design scales do not define measurement uncertainty.

Measurement mode factors each supplied covariance as `C = L L^T`, applies `L^-1` to residuals and Jacobians, and assumes different epochs are independent. This preserves within-epoch position/velocity cross-correlations. Position-only fits use the covariance's position block. Block Huber loss, when enabled, acts on the full whitened residual at each epoch. Neither mode currently exports a parameter covariance; a covariance computed from ephemeris samples alone could imply unjustified statistical confidence.

Ceres uses Levenberg–Marquardt, Eigen `DENSE_QR`, Jacobian column scaling, and a single evaluation thread. `src/estimation.cpp` owns the solver adapter; `src/initialization.cpp` owns coarse seeding, `src/evaluation.cpp` computes physical diagnostics, and `src/fit.cpp` orchestrates acceptance. The initial trust-region radius is 1e3 and the minimum is 1e-12. A callback retains the stationarity test `max_j |A_j^T r| / ||A_j|| <= gradient_tolerance`, where `A` and `r` are the whitened, optionally robustly reweighted linearization and zero columns contribute zero. Scaling by column norms prevents mean motion's much larger sensitivity on long arcs from dominating the termination decision. The callback evaluates immutable factors directly; Ceres forbids `Problem::Evaluate` during a solve. This is a local stationarity test in whitened residual units; it does not establish identifiability.

Ceres owns relative cost convergence through `function_tolerance = relative_cost_tolerance`; its test is `|cost_change| <= relative_cost_tolerance * cost`. This includes floating-point cost plateaus. Native gradient and parameter tolerances are zero; their exact-zero exits remain valid numerical convergence. The callback adds the absolute-cost and column-scaled-gradient criteria. A converged solve need not satisfy all criteria simultaneously, and numerical convergence does not establish physical accuracy. Rejected trials continue through Ceres' trust-region logic; the callback explicitly reports exhausted trust-region radius as stalled. This avoids treating Ceres' radius-limit exit as convergence. Iterations count the entries reported by Ceres excluding initialization; a terminal convergence check can exit before another entry is recorded. This differs from the previous GTSAM outer-iteration count. Cancellation is checked during input validation, factor construction/evaluation, iteration monitoring, and final physical evaluation. It can preserve the last candidate with incomplete diagnostics; it cannot interrupt a single propagation or linear algebra operation. Numerical failures and exhausted iteration budgets cannot produce accepted fits.

A candidate is accepted only after convergence, full numerical rank, and the configured in-window RMS position gate. Rank uses the singular values of the final whitened (and, when applicable, robustly reweighted) Jacobian at relative threshold 1e-8. Ceres' Huber correction uses the same first-order robust weights as the callback. Conditioning depends on the chosen coordinate scaling and is a local diagnostic, not proof of global identifiability. Solver success alone does not establish acceptable TLE output; serialization is evaluated separately.

TLE export rounds the epoch to exact 864-microsecond ticks before extracting year and day, handles angular and mantissa carry, validates field widths, and computes checksums. `prepare_products` reparses both actual exported formats and evaluates each model against all in-window samples. Its owned delivery snapshot supplies the CLI and report v2 with the same decision: continuous acceptance and OMM accuracy are mandatory; TLE accuracy is also mandatory under the default `tle_required` policy. `omm_sufficient` explicitly permits an unavailable or inaccurate TLE. OMM preserves floating-point round-trip precision and supports larger catalog IDs. SGP4 does not use the TLE mean-motion derivative fields; exports set them to zero. See [delivery workflows](workflows.md) and [internal contracts](internals.md).

The public Vallado reference outputs test propagation conformance to a known SGP4 implementation. Synthetic recovery tests test fitting consistency. Neither demonstrates agreement with the true trajectory of a spacecraft. The [ISS campaign](../qualification/README.md) adds a NASA forecast, explicit frame conversion, an external fitter, and held-out epochs. It measures forecast approximation; observed-trajectory accuracy still requires independent tracking evidence.
