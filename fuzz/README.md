# Parser and serialization fuzzing

`parsers.cpp` exercises UTC timestamps, numeric TLEs, GP OMM JSON, request JSON, and successful serialization round trips. The harness caps inputs at 64 KiB and does not run nonlinear fitting. A successful parse must support its applicable round trip; valid OMM sets outside legacy TLE limits may decline TLE export. Production JSON limits remain 64 MiB and depth 32, separately exercised by unit tests. This campaign is not exhaustive security or service-resource qualification.

Use Clang with a complete C++23 standard library, libFuzzer, and the same Ceres dependencies as the main build:

```sh
cmake -S . -B build/fuzz -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DORBITFIT_BUILD_TESTS=OFF -DORBITFIT_BUILD_CLI=OFF \
  -DORBITFIT_BUILD_FUZZERS=ON -DORBITFIT_SANITIZERS=ON
cmake --build build/fuzz --parallel 3
mkdir -p build/fuzz/corpus build/fuzz/artifacts
cp fuzz/corpus/* build/fuzz/corpus/
build/fuzz/orbitfit_fuzz build/fuzz/corpus -seed=20261024 \
  -max_total_time=90 -timeout=10 -rss_limit_mb=2048 -max_len=65536 \
  -artifact_prefix=build/fuzz/artifacts/ -print_final_stats=1
```

Select Clang through `CC`/`CXX` before configuring. If dependencies are already installed, add `-DCPM_USE_LOCAL_PACKAGES=ON -DCMAKE_PREFIX_PATH=/absolute/install/prefix`. Project sources and the Vallado kernel receive ASan/UBSan and libFuzzer coverage instrumentation; preinstalled Ceres/glog do not.

AppleClang 21 does not bundle the libFuzzer archive on the tested machine. The local campaign used the upstream LLVM 18.1.8 runtime via `-DORBITFIT_FUZZER_RUNTIME=/opt/homebrew/opt/llvm@18/lib/clang/18/lib/darwin/libclang_rt.fuzzer_osx.a`, retaining AppleClang 21 compilation and sanitizer runtimes. This explicit override is optional for compiler distributions that already ship libFuzzer.

Seed corpus provenance: request and OMM files are synthetic outputs generated by orbit-fit's example; `epoch.txt` is an authored timestamp boundary seed; `tle.txt` is the six-hour fixed-drag ISS numerical output whose source is documented in `tests/data/independent/README.md`. Campaign and corpus curation: watson. The corpus intentionally retains exact parser inputs without author comments. Mutated corpus files and artifacts stay in ignored build directories. Minimize any failure, retain it as a regression seed, and add a focused assertion when fixing its cause.

The CLI's YAML/CSV loader has separate malformed-input, size/depth/sample-boundary, cancellation, and replay tests under ASan/UBSan. This libFuzzer harness covers the numerical library parsers, not the file-based YAML/CSV adapter or upstream yaml-cpp. Recorded campaign results and scope are in [validation](../docs/validation.md).
